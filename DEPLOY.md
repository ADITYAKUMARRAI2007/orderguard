# Deploying OrderGuard (Render)

A live, public deployment of exactly what's in this repo — test-mode
Razorpay, single-tenant, SQLite on one machine, same honest scope as
[LIMITATIONS.md](LIMITATIONS.md). Not a production hardening pass; see that
file for what this deliberately does not claim.

Two separate Render services: the FastAPI backend, and the React frontend
as a static site. **I cannot create these for you** — creating a Render
account/service and entering real Razorpay/Anthropic/LLM keys has to happen
in your own browser, in Render's own dashboard, so those secrets never pass
through this chat or get written into the repo.

## 1. Backend

1. Push this repo to GitHub (already done).
2. In Render: **New +** → **Blueprint** → connect this repo. Render reads
   [`render.yaml`](render.yaml) at the repo root and proposes one service,
   `orderguard-backend`, with a 1GB persistent disk for the SQLite
   databases under `data/`.
3. Render will prompt you to fill in every `sync: false` env var from
   `render.yaml` — **your real values, typed directly into Render's form,
   never shared with me**:
   - `RZP_KEY_ID`, `RZP_KEY_SECRET` — Razorpay **test-mode** keys
     (dashboard.razorpay.com → Test Mode → API Keys).
   - `RZP_WEBHOOK_SECRET` — optional; without it the webhook endpoint
     fails closed rather than accepting an unverifiable delivery.
   - `LLM_API_KEY` — your Gemini key (aistudio.google.com/apikey), or
     change `LLM_PROVIDER`/`LLM_MODEL` env vars to `groq`/your own model
     first if you'd rather use that.
   - `SEARCH_API_KEY` — optional (serper.dev); web search is simply absent
     without it.
   - `ANTHROPIC_API_KEY` — needed since `render.yaml` sets
     `AGENT_RUNTIME=api`. (The `subscription` runtime needs a
     `CLAUDE_CODE_OAUTH_TOKEN` generated by `claude setup-token` in your
     own terminal — this project never automates that step — swap
     `AGENT_RUNTIME` to `subscription` and add that var instead if you
     want that path live too.)
   - `CONNECTOR_TOKEN_KEY` — generate once with:
     ```bash
     python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
     ```
   - `ALLOWED_ORIGIN` — leave blank for now; step 3 below.
4. Deploy. Render gives you a URL like
   `https://orderguard-backend.onrender.com`. Confirm it's alive:
   ```bash
   curl https://orderguard-backend.onrender.com/api/runtime/status
   ```

## 2. Frontend

1. In Render: **New +** → **Static Site** → same repo.
2. **Root Directory**: `frontend`
3. **Build Command**: `npm ci && npm run build`
4. **Publish Directory**: `dist`
5. Add one env var **before the first build**: `VITE_API_BASE_URL` =
   the backend URL from step 1.4 (no trailing slash), e.g.
   `https://orderguard-backend.onrender.com`. Vite bakes this in at build
   time — if you add it after the first deploy, trigger **Manual Deploy**
   again for it to take effect.
6. Deploy. Render gives you a URL like
   `https://orderguard-frontend.onrender.com` — **this is the link to share
   with judges.**

## 3. Wire the two services together

The backend's CORS is locked to one origin once `ALLOWED_ORIGIN` is set
(see `src/orderguard/app.py`) — without it, it defaults to allowing
everything, which is fine for testing but worth tightening for the real
deployment:

1. Backend service → **Environment** → set `ALLOWED_ORIGIN` to the
   frontend URL from step 2.6 (no trailing slash).
2. Save — this restarts the backend (no rebuild needed, it's read at
   startup from `os.environ`).

## 4. Verify

Open the frontend URL. Run a real order through Shop end to end and
confirm the Razorpay Checkout modal opens against your test-mode key — the
same flow already proven locally throughout this project's development.
The Connectors page's "Connected via your Claude account" panel will show
whatever `claude mcp list` reports were it to run on Render's machine,
which is nothing (no Claude Code CLI runs there) — that panel is honestly
a local-machine-only feature, not a deployment bug.

## What this deployment does not attempt

Real auth, multi-tenancy, high availability, a durable hosted database in
place of SQLite, or real (non-test-mode) payments — see
[LIMITATIONS.md](LIMITATIONS.md). Free-tier Render web services also spin
down after inactivity and take a few seconds to wake on the next request;
worth knowing before a live judge demo, not something this repo's code
controls.
